Fix sign-in and sign-up failing silently

The reported symptom was "I cannot sign in or sign up". The root cause was not
one bug but a chain of them: every failure below was invisible, so the form
appeared to do nothing at all.

Surfaced the real errors
- The sign-in and sign-up form called the action with no try/catch. Any thrown
  action — a database failure, a rate limit, a dropped connection — left the
  button disabled on "Creating account…" forever with no message. The handler
  now catches, reports, and clears its pending state in a finally.
- A database failure now returns a specific message naming the fix
  (`npm run db:migrate`) instead of rethrowing into the void.

Made a broken database stop taking down the sign-in page
- `getUserId()` threw when the session lookup failed, so with an unreachable
  database the sign-in page itself rendered the error boundary: the one screen
  that could explain the problem was the screen that disappeared.
- It now resolves to null on a database error. That is the safe direction — an
  unverifiable session is not a session — and it degrades to "you are signed
  out", so the form still renders and can report what went wrong.

Fixed the fresh-clone setup
- `data/` is gitignored, so a new clone has nowhere to put the SQLite file, and
  SQLite cannot create its own parent directory. Every query failed with an
  "unable to open database" that gave no hint why. `lib/db.ts` now creates the
  directory on first run.
- The README told people to run `mkdir -p data`, which does not work in cmd.exe
  on Windows. Removed now that the app handles it.

Loosened the rate limiter
- 60 requests per minute per IP is tripped by ordinary clicking, because one
  page view fans out into RSC prefetches and navigations. Raised to 300, with
  sign-in brute force throttled per account where it belongs.

Verified by reproducing the failure
- Removed the database entirely: the sign-up page still renders, `data/` is
  recreated automatically, and submitting reports "Couldn't reach the database.
  Make sure the data directory exists and the migrations have been applied with
  `npm run db:migrate`" instead of hanging.
- Restored the database: sign-in succeeds and lands on the freelancer overview,
  confirming role-aware rendering is still per user.
- TypeScript clean, ESLint clean, production build passes, all 15 routes
  generate.
